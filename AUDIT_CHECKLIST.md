# Audit checklist

Use this list when reviewing a change to the corpus. Items marked *verified*
were checked against the repository state at the time the current pins were
recorded. Re-run the commands after any source change.

## Toolchain and dependencies

- [ ] `lean-toolchain` pins an exact Lean release.
  - Current: `leanprover/lean4:v4.33.0`
- [ ] `lakefile.toml` pins mathlib to a matching revision or tag.
  - Current: `rev = "v4.33.0"`
- [ ] `lake-manifest.json` records the resolved mathlib commit.
  - Current: `db584cd6d46c92f209a44c0f1c829460d327499d`
- [ ] The Lean toolchain and mathlib tag are the same version family.
- [ ] `lake-manifest.json` was generated by `lake update`, not edited by hand.

## Build

- [ ] Mathlib cache is fetched before a clean build: `lake exe cache get`
- [ ] Targeted module builds succeed during development:
  - `lake build ProofEngineering.Foundations`
  - `lake build ProofEngineering.StructuredProofs`
  - `lake build ProofEngineering.Rewriting`
  - `lake build ProofEngineering.Algebra`
  - `lake build ProofEngineering.Induction`
  - `lake build ProofEngineering.TypeDrivenReasoning`
  - `lake build ProofEngineering.Robustness`
  - `lake build ProofEngineering.ReviewerCases`
- [ ] Full build succeeds: `lake build`
- [ ] The full build is repeated after the last source edit.

## Soundness holes

- [ ] No `sorry` in project `.lean` files (exclude `.lake`): `bash scripts/check_no_sorry.sh`
- [ ] No `admit` in project `.lean` files
- [ ] No custom `axiom` declarations in project sources
- [ ] Classical reasoning uses Lean's existing `Classical` interface only
      (`Foundations.not_not_iff`)

## Theorem faithfulness

For each changed theorem:

- [ ] The type / carrier is the intended one (`Nat` vs `Int` vs `Rat` vs `Real`)
- [ ] Required hypotheses are present (nonzero, positivity, divisibility, order)
- [ ] No unused hypothesis was added merely to silence a linter
- [ ] Quantifier order matches the mathematical claim
- [ ] Implication direction is correct
- [ ] The statement is not vacuously true for a reason foreign to the intent
- [ ] A stronger or weaker proposition was not substituted to obtain compilation
- [ ] Edge cases (`0`, empty lists, `b > a` on `Nat`) were considered

## Defective examples

- [ ] Intentionally broken statements appear only as comments or Markdown
- [ ] No defective snippet is a compilable declaration
- [ ] Each reviewer case has a corrected executable theorem
- [ ] The repair preserves the intended meaning (see C01–C05)

## Documentation consistency

- [ ] `README.md` environment table matches `lean-toolchain` and `lakefile.toml`
- [ ] `README.md` architecture list matches files that exist
- [ ] `CASE_INDEX.md` lists only cases that exist
- [ ] Every major case still has the seven documentation fields
- [ ] Difficulty counts in `CASE_INDEX.md` match the table

## CI

- [ ] `.github/workflows/ci.yml` triggers on push to `main`
- [ ] `.github/workflows/ci.yml` triggers on pull requests to `main`
- [ ] Workflow checks out the repository
- [ ] Workflow rejects `sorry` and `admit` before the Lean build
- [ ] Workflow uses `leanprover/lean-action@v1`
- [ ] `build: true` is set
- [ ] Mathlib cache is enabled (`use-mathlib-cache: true`)
- [ ] Nanoda is not enabled
- [ ] CI is not marked successful unless `lake build` succeeds

## Known warnings

Record warnings that are accepted rather than hidden:

- None accepted at the last full build. New warnings should be fixed or listed
  here with a reason.

## Known limitations

- The corpus is a designed sample, not a research formalization.
- Several identities already exist in mathlib and are re-proved for structure.
- `import Mathlib.Tactic` keeps import sets larger than minimal.
- Defective reviewer snippets are not typechecked.
- Lean / mathlib APIs change; only the pinned pair is supported.

## Commands

```bash
cat lean-toolchain
sed -n '1,20p' lakefile.toml
python3 -c "import json; m=json.load(open('lake-manifest.json'));
print([p for p in m['packages'] if p['name']=='mathlib'][0]['rev'])"
bash scripts/check_no_sorry.sh
lake exe cache get
lake build
```
